# Task Service Contract

This directory contains the in-browser REST-like task service used by the MVP. The service is a TypeScript abstraction for the React single-page application; it is not a network-accessible REST API.

Task records are stored in browser `localStorage` under the current origin. Data is local to the same browser and origin and is not shared across browsers, devices, or users. The MVP does not include an external network API, authentication, authorization, or a server database.

## Domain Values

Task status values:

- `Pending`
- `Completed`

Task priority values:

- `Low`
- `Medium`
- `High`

## Data Shapes

`Task`:

```ts
{
  id: string;
  title: string;
  description?: string;
  dueDate: string;
  priority: "Low" | "Medium" | "High";
  status: "Pending" | "Completed";
}
```

All service functions return `TaskServiceResponse<T>`.

Success response:

```ts
{
  ok: true;
  status: number;
  route: string;
  method: "GET" | "POST" | "PUT" | "PATCH" | "DELETE";
  data: T;
}
```

Failure response:

```ts
{
  ok: false;
  status: number;
  route: string;
  method: "GET" | "POST" | "PUT" | "PATCH" | "DELETE";
  error: {
    code:
      | "storage_unavailable"
      | "read_failed"
      | "write_failed"
      | "clear_failed"
      | "invalid_data"
      | "not_found"
      | "invalid_request"
      | "validation_failed";
    message: string;
    fieldErrors?: Array<{
      field: "title" | "dueDate" | "priority";
      message: string;
    }>;
  };
}
```

## Operations

### `GET /tasks?status={Pending|Completed}`

Function: `getTasks(query?: { status?: "Pending" | "Completed" })`

Returns all locally stored tasks, sorted by due date ascending. When `status` is provided, only tasks with the matching status are returned.

Request behavior:

- `status` is optional.
- Valid status filter values are `Pending` and `Completed`.

Success response:

- `200 OK`
- `data` is `Task[]`.
- `route` is `/tasks` when no filter is provided.
- `route` is `/tasks?status=Pending` or `/tasks?status=Completed` when filtered.

Error states:

- `400 invalid_request` when `status` is present but is not `Pending` or `Completed`.
- `500 storage_unavailable`, `500 read_failed`, or `500 invalid_data` when local task storage cannot be read.

### `POST /tasks`

Function: `postTask(input)`

Creates a new locally stored task. New tasks always start with `status: "Pending"`.

Request body:

```ts
{
  title?: string;
  description?: string;
  dueDate?: string;
  priority?: "Low" | "Medium" | "High" | "";
}
```

Request behavior:

- `title`, `dueDate`, and `priority` are required.
- `priority` must be `Low`, `Medium`, or `High`.
- `title` and `description` are trimmed before storage.
- Empty `description` is stored as `undefined`.
- `id` is generated by the service.

Success response:

- `201 Created`
- `data` is the persisted `Task`.
- `route` is `/tasks`.

Error states:

- `400 validation_failed` when required fields are missing or `priority` is invalid. `fieldErrors` identifies `title`, `dueDate`, and/or `priority`.
- `500 storage_unavailable`, `500 read_failed`, or `500 invalid_data` when local task storage cannot be read.
- `500 storage_unavailable` or `500 write_failed` when local task storage cannot be written.

### `GET /tasks/{id}`

Function: `getTask(id: string)`

Returns one locally stored task by `id`.

Request behavior:

- `id` is passed as the path parameter.
- The response route encodes the `id` in `/tasks/{id}` form.

Success response:

- `200 OK`
- `data` is the matching `Task`.

Error states:

- `404 not_found` when no task exists for the provided `id`.
- `500 storage_unavailable`, `500 read_failed`, or `500 invalid_data` when local task storage cannot be read.

### `PUT /tasks/{id}`

Function: `putTask(id: string, input)`

Replaces the editable fields for an existing locally stored task. The current stored task status is preserved by the service.

Request body:

```ts
{
  title: string;
  description?: string;
  dueDate: string;
  priority: "Low" | "Medium" | "High" | "";
  status: "Pending" | "Completed";
}
```

Request behavior:

- `id` is passed as the path parameter.
- `title`, `dueDate`, and `priority` are required.
- `priority` must be `Low`, `Medium`, or `High`.
- `status` must be `Pending` or `Completed`, but the service preserves the stored task status instead of replacing it from this input.
- `title` and `description` are trimmed before storage.
- Empty `description` is stored as `undefined`.

Success response:

- `200 OK`
- `data` is the persisted updated `Task`.

Error states:

- `400 invalid_request` when `status` is not `Pending` or `Completed`.
- `400 validation_failed` when required fields are missing or `priority` is invalid. `fieldErrors` identifies `title`, `dueDate`, and/or `priority`.
- `404 not_found` when no task exists for the provided `id`.
- `500 storage_unavailable`, `500 read_failed`, or `500 invalid_data` when local task storage cannot be read.
- `500 storage_unavailable` or `500 write_failed` when local task storage cannot be written.

### `PATCH /tasks/{id}/complete`

Function: `patchTaskComplete(id: string)`

Marks one locally stored task as `Completed`.

Request behavior:

- `id` is passed as the path parameter.
- No request body is accepted.
- Completing an already completed task is idempotent and returns the existing completed task.

Success response:

- `200 OK`
- `data` is the completed `Task`.

Error states:

- `404 not_found` when no task exists for the provided `id`.
- `500 storage_unavailable`, `500 read_failed`, or `500 invalid_data` when local task storage cannot be read.
- `500 storage_unavailable` or `500 write_failed` when local task storage cannot be written.

### `DELETE /tasks/{id}`

Function: `deleteTask(id: string)`

Removes one locally stored task.

Request behavior:

- `id` is passed as the path parameter.
- No request body is accepted.

Success response:

- `204 No Content`
- `data` is `null`.

Error states:

- `404 not_found` when no task exists for the provided `id`.
- `500 storage_unavailable`, `500 read_failed`, or `500 invalid_data` when local task storage cannot be read.
- `500 storage_unavailable` or `500 write_failed` when local task storage cannot be written.

## MVP Boundary

These REST semantics are internal service contracts only. Replacing this abstraction with a real HTTP API later should preserve the operation names, request shapes, response shapes, status values, and error meanings documented here, but the MVP does not expose any HTTP routes and does not use an external API version.
